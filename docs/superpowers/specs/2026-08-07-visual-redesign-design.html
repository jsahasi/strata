Visual redesign — design spec

Written 2026-08-07, after a brainstorm on the same date. Covers the corporate site (deploy/site/) and the application web pages (app/web/). Supersedes the visual direction recorded in docs/web-design.html Parts two and three.

This is a spec, not a plan. It says what is being built and why. The step-by-step implementation plan is a separate document, written after this one is approved.

1. Why this work is happening

The current surface was built inside a 48-hour window and defended in writing at the time. It is restrained on purpose: two hues, system fonts, no build step, no web font, a 12px type floor for an analyst who is often 40-plus and often on a laptop in somebody else's meeting room. That restraint was correct for the build it was made in.

The judgement now is that it undersells a finished product. The direction chosen is institutional fintech confidence — the register of Stripe, Ramp, Mercury. Light and open, large confident type, a real colour system, generous space, considered motion.

The named risk, and the brief that follows from it. This direction is the most templated of the ones considered. A panel may read it as a slide deck. That risk was accepted with open eyes, which makes it the design brief: institutional confidence without looking templated. Every decision below is measured against that, and the three moves that do the most work are the display-only web font, the gradient ban on record surfaces, and the refusal as the hero image.

4. Type

The decision

Self-host one variable font and use it for display only. Keep the system stack for interface text and data.

Everything in this category ships Inter for everything, which is exactly the templated look the brief exists to avoid. Splitting display from interface is cheaper, faster and more distinctive than the usual answer.

TokenFaceUsed for
--face-displayManrope variable, weights 400-800, Latin subsetHeadlines, hero, section titles, large counts
--face-uiunchanged system stackAll interface text, tables, forms, dense screens
--face-docunchanged serif stackQuoted source text, the record
--face-dataunchanged monospaceCodes, coordinates, identifiers

Verified, not assumed

  • Licence: SIL Open Font License 1.1. Copyright 2018 The Manrope Project Authors. Self-hosting is permitted; OFL.txt ships beside the font.
  • Payload: 24,576 bytes for the Latin subset covering the whole 400-800 range in one file. Verified wOF2 magic bytes.
  • Fetched at build time from Google's CDN and committed to the repository. No runtime CDN dependency. The reviewer's machine needs no network.

Rules

  • Two copies, one per surface: app/web/static/ and deploy/site/. The publish step does not cross the boundary, so the duplication is deliberate.
  • font-display: swap with a metric-compatible system fallback so the swap does not reflow the page.
  • <link rel="preload"> on the hero pages only, not on every page.
  • All figures get font-variant-numeric: tabular-nums. A data product whose numbers jitter between renders looks broken.
  • The 12px floor survives. It was set for a real user on real hardware, and nothing about this direction argues against it.

5. Colour

The system

  • Primary: a deep institutional indigo-blue, carrying anything actionable.
  • Accent: a warmer companion, used only in gradients, and so confined to the surfaces the second rule below allows.
  • Semantic set: positive, caution, refusal, info. Refusal keeps the oxblood weight it has now, because it is the product's signature state.
  • Neutrals: warmed slightly off pure grey so the page reads as one family.
  • Each of the four schemes gets its own coordinated values. Nothing is derived by blanket inversion.
No hex values are fixed in this spec, and that is deliberate. Naming a colour here and computing its contrast later is the wrong order: the test in §3 requires every published ratio to be true, so the values are chosen against the ratio script, not before it. The spec fixes the roles and the rules; the plan fixes the numbers. Picking hexes here would only guarantee rework.

Two rules that keep it honest

Meaning never rests on colour alone. Label, weight and shape carry state first. This survives the rewrite unchanged. It is an accessibility requirement and a product argument at the same time, and the existing screens already obey it.

Gradients and mesh live on the marketing site and the application chrome only. The record stays flat paper. The diff, the claims, the quoted source and the citation viewer get no gradient, no mesh, no tint. A gradient behind a piece of evidence undermines the thing this product sells. This is the rule that stops the chosen direction turning into decoration, and it is enforced by a new test rather than left to discipline.

6. Motion

Raised mid-brainstorm and promoted to its own section. The implementation draws its curves and durations from the animate and transitions-dev skills rather than from invented numbers.

Every item below ships a prefers-reduced-motion path in the same stylesheet. That is not politeness; test_a11y_guards.py:357 fails the build without it. Reduced motion shows the end state immediately — it never shows nothing.

Explicitly rejected

  • Count-up number animations. A gimmick, and it fights the tabular-figure honesty in §4. A figure that animates from zero is briefly wrong on screen.
  • Parallax inside the application. Marketing only, and even there kept slight.
  • Scroll-jacking anywhere. It breaks keyboard and screen-reader navigation.
  • Animated gradient meshes on record surfaces. Already banned by §5; restated here because it is the most tempting rule to break.

7. The marketing site

The existing section order is sound. The hero is the weak point.

  1. Hero — the refusal. Not a product screenshot. A claim declining to assert itself because its citation did not verify. The submission brief requires the hardest technical decision to be visible in the product; this puts it in the first screenful of the public site.
  2. How it works. A real inline-SVG mechanism diagram showing source, extraction, verification and the gate. No stock illustration.
  3. What it refuses to do. The differentiator, given room.
  4. Who it is for. One user, per the project's own rule.
  5. The film and the closing call to action.

Inheriting the system without individual redesign: security.html, privacy.html, terms.html, subprocessors.html, login.html, 404.html and the blog.

9. Documentation

  • ADR revisiting ADR-012 — the web font, narrowly. No build step and no CDN both survive; only "no web font" falls.
  • New ADR — palette beyond two hues. Must say why the old rule was right for a 48-hour build and wrong for a finished product. An ADR that only says "we wanted more colours" is worth nothing at a panel.

  • docs/.ai/decisions.html carries all three, per the project's own rule that the ADR ships in the same change as the decision.

10. Acceptance

  • All 2,340 tests stay green. That is the bar, not a hope. make fresh-check exits zero.
  • Every contrast ratio in a comment is computed by script, never estimated.
  • New guard: no stylesheet or template references a font CDN; the font is served from the repository.
  • New guard: record surfaces carry no gradient.
  • Keyboard walk of the six hand-tuned screens: focus ring visible on every stop and never trapped behind the sticky header.
  • All four schemes checked by eye, not only by test.

11. Risks

RiskHandling
The chosen direction reads as templated — the risk accepted at the brainstormThe three counter-moves in §1. If the hero still looks generic when built, that is a signal to revisit, not to ship.

12. Out of scope

  • Application behaviour, routes, permissions and data. This is a visual change.
  • The nine open items on docs/.ai/gaps.html. Unrelated, and mixing them in would make both harder to review.
  • Re-recording the demo film. It becomes stale the moment the restyle lands, and that is worth recording as a new gap rather than doing inside this work.
  • The blog's individual posts. The blog inherits the system; the writing is untouched.
