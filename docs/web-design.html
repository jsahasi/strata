Web Surface and Deployment

The design for what a reviewer sees at strata.sudama.ai, and how it gets there. Two surfaces: the application, and the marketing site in front of it.

What this document is, and when each part was written. Part one was written 2026-08-03, before app/ existed. Part two was written 2026-08-04 as a plan for the visual revision. Both have since shipped, so on 2026-08-04 the whole document was read back against the files and every claim that had gone false was corrected. It now says what the code does, in the present tense. Where a passage records a decision or a measurement from before the build, it says so and gives the date. Where nobody has checked, it says nobody has checked — those admissions are in What is still not known near the foot, and they are not padding.

The pipeline behind the screens — ingestion, diff, interpretation, verification, state — is specified in docs/architecture.html and is unchanged by anything here. The reasoning for each choice below lives in docs/.ai/decisions.html as ADR-009 through ADR-014.

The sequencing risk, and how it turned out. Written first on 2026-08-03 because it governed everything else: app/ and tests/ were empty, so the web layer would render state that nothing yet produced. The build order chosen was verifier and diff before screens, and the deployment before the design polish. That order held. The engine landed first, the screens second, the deployment third and the visual revision last, which is why part two below could be written against screenshots of a running product rather than against a sketch. Nothing in the cut order at the end of part one was cut.

The citation viewer

This is the interaction the submission rests on, so it is specified rather than sketched.

Every claim on change detail carries a citation chip showing the section reference. Activating the chip opens a source panel beside the claim, scrolled to the cited character offsets, with the exact quoted span marked in the original document text. The paired demonstration. Two changes, shown one after the other. The first verifies: the chip is solid, the span highlights, the claim reads as established fact. The second carries a deliberately corrupted quote. It never renders as a claim at all. It appears in the review queue, labelled with the reason and showing the mismatch — what was quoted, against what the source actually says at those offsets.

Constraint on the visual design, and it is a hard one. Verified and unverified must not read as two shades of a single treatment. A greyed-out assertion is still an assertion — the reader's eye completes it. The unverified state has to differ in structure, not only in colour: the claim text does not appear in the position where claims appear, and what occupies that position is the reason it was withheld. It must work without a legend, and it must survive being screenshotted in black and white.

Design system

Four stylesheets, each organised as tokens then components, with every colour declared once in strata.css. The constraints below were set on 2026-08-03 and all four still hold; part two says what was drawn inside them.

  • Type. A scale built for dense regulatory prose, not for dashboard chrome. Quoted source passages need a real measure — around 66 characters — and generous leading, because the analyst reads them rather than scans them. Interface text and document text are visibly different registers, so a quotation is never mistaken for the product's own voice.
  • Colour. Greyscale carries the structure. One accent for interactive elements, one for escalation. Materiality and draft-versus-final are conveyed by label and weight first, colour second, so the meaning survives colour blindness and a monochrome screenshot.
  • Both schemes. Light and dark, via prefers-color-scheme. Tokens are declared once and inverted, not redefined per component.
  • No dependencies. No CSS framework, no icon font, no web font fetched from a third party. System font stack. Every byte the page loads is served from the same origin, which also keeps the content security policy simple.

These four constraints were written before a line of CSS existed. Part two is what got drawn inside them, and none of the four was relaxed to make the glass work — the closest call is the type register rule, which is why long prose never sits on a translucent surface anywhere in the product.

The seam is a named list, and that is the decision worth defending. deploy/nginx.conf line 65 matches one regex:

location ~ ^/(login|logout|projects|proceedings|changes|review|escalations|workflow
              |admin|chat|feedback|users|invite|s|static|healthz)(/|$)

Everything else falls through to try_files and the static site. A catch-all would fail quietly in both directions: a page added to the site would silently reach the app, and a router added to the app would silently 404. Writing the list down makes the seam a thing somebody must edit on purpose. The cost is real and stated: a new top-level route needs a line here or it is unreachable in production and perfectly fine in every test. No test catches that.

Properties. Two containers, one compose file. The app publishes no port — expose: "8000", not ports: — and carries no Traefik labels, so nginx is the only thing that can reach it. SQLite is a host bind mount, not a named volume as this section originally said: /data/strata/db:/data, with STRATA_DATABASE_URL=sqlite:////data/strata.db. A redeploy replaces the image and keeps the data, which for this product means keeping the audit chain — the one thing that cannot be regenerated, because regenerating it is indistinguishable from rewriting it.

The entrypoint migrates before it reads. deploy/entrypoint.sh runs scripts/migrate.py always, before anything touches a table, then seeds only when the database file is absent, then execs uvicorn. The migration exists because the deploy after a new column would otherwise have kept yesterday's table under today's code and answered every screen with no such column. Tests build their schema from the current models every time, so they never meet yesterday's database; this is a failure only production can have.

The local contract, restated accurately. The original text claimed the Dockerfile calls the same entrypoint as make run. It does not, quite: make run is seed then uvicorn with --reload, while the container entrypoint adds the migration and the seed-only-if-absent guard. What is true, and is the part that matters, is that there is no deployment-only application code path — both run app.main:app unchanged. make test stays offline and does not know the host exists.

Failure behaviour

The deployed instance obeys the same rule as the local one: absence is denial. Deployment must not become the place that principle quietly stops applying.

ConditionBehaviour
Database emptyThe page says the corpus has not loaded, and how to load it. It does not render an empty table that reads like "nothing has changed".
Verification cannot runNo claim renders as established. Everything routes to review. The product degrades to useless-but-honest rather than confident-and-wrong.
Model unavailableIngestion, diff and citation verification continue — they need no model. Interpretation degrades visibly to escalation, with the reason shown, per principle 26: a fallback must announce itself.

The suite is offline, deterministic and asserted against the corpus manifest's known answers. It runs with:

This section originally promised "three checks and no more" for the deployment. That number is long past. The checks that guard this document's subject matter — the web surface — are:

  1. /healthz returns 200 with the corpus row counts across five tables (app/main.py lines 107–120), so an empty database fails loudly instead of rendering empty screens that read like "nothing has changed".
  2. tests/test_responsive.py — fixed widths, table scrolling, the viewport tag, long unbreakable tokens, and since 2026-08-04 the marketing site as well. See Part three.
  3. tests/test_chat_surface.py and tests/test_tour.py — the no-hex rule that keeps clerk.css and tour.css inside one palette.

These tests read stylesheets and markup; they cannot lay out a page, so they cannot prove either surface looks right on a handset — only a browser at a real width can, and the 390px figures quoted in this document come from a headless Chromium at a fixed viewport, not a phone. (3) Prose. There is no guard on a document like this one. The idea, in one paragraph

macOS has never applied vibrancy uniformly: sidebars, toolbars and popovers are translucent, and the document canvas is opaque. This product borrows that split and gives it a meaning it does not have on a desktop. The chrome is glass and the record is paper. Navigation, panels, rails and controls take the translucent treatment, because you look past them a thousand times a day. Claims, citations, quoted source text, the diff and the audit trail stay flat, opaque and still, because a document a regulator may read should not shimmer. Blur behind body text costs legibility, and a translucent tariff clause is a worse tariff clause.

Then one surface goes further than paper, and it is the whole argument:

The withheld claim is the one surface in the product with no effect on it at all. No blur, no shadow, no transform, no transition, no animation, no hover, no cursor change. It is deliberate, and it is the most important sentence in this document: the moment the product refuses to assert something is the moment it must look least like a decoration. Everything else on a Strata screen answers a cursor. A reviewer who moves across a change page and feels the interface go dead at exactly the claim the system declined to assert has understood the product without being told. The full specification is in The signature.

The glass ladder: three levels, and the rule that sets them

Three, and no fourth. The rule that fixes the alphas is the opposite of the reflex:

The longer a surface lives and the more words it carries, the more opaque it is. The masthead holds two words per item and you look past it a thousand times, so it can be the most transparent thing on screen. A tour tip holds a paragraph you must read once and dismiss, so it is nearly solid. The reflex — small and fleeting means see-through — produces exactly the wrong legibility, and it is where most glass work fails.

Three micro-interactions

M1 — the chip opens the source. The product's central interaction, so it is the most restrained.

  • Chip fill: background-color and color, 120ms ease. Already in the sheet. Unchanged.
  • Source panel reveal: opacity 0→1 and translateX(6px)→0, 200ms --ease-sheet. No scale, no overshoot. An overshoot on a panel showing the text of an order would be a small lie about how serious the thing is.
  • The marked span inside it: no motion at all. It is already correct when it arrives. A highlight that animates in asks to be watched rather than read.

M2 — the dock arrives. transform: translateX(100%)→0 plus opacity 0→1, 340ms --ease-sheet. No scrim: the dock sits beside the page rather than over it, and a scrim would hide the screen it exists to answer questions about. No overshoot: a 26rem rail that overshoots shows a strip of nothing at the viewport edge.

M3 — the suggestion pills. The one spring in the product. opacity 0→1, translateY(6px)→0, scale(0.96)→1, 240ms --ease-offer, which overshoots about four percent. Stagger 40ms per pill, capped at four — a fifth pill arrives with the fourth. A stagger running past roughly 200ms stops reading as one gesture and starts reading as a queue. This is the only overshoot anywhere, and it is here because a suggestion is the only thing on screen that is an offer rather than a record. Nothing rests on it, so it may be light.

Two ambient behaviours, written down so a third does not get invented:

  • A1 Project card hover: translateY(-1px) and box-shadow: none → var(--shadow-3), 160ms --ease-settle. One pixel, not four.
  • A2 Buttons, tabs, chips, nav: 120ms ease on colour only. Exactly what is there now. Do not add transform.

Arrivals animate. Departures do not.

Both the dock and the source panel are toggled with the hidden attribute, which strata.css forces to display: none !important. A transition cannot run out of display: none, but a CSS animation restarts every time an element becomes displayed — so both reveals above are animations, and neither needs a line of JavaScript changed. Closing is instant, and that is a decision rather than a limitation: a person closing a panel has already decided, and making them watch it leave is the commonest small rudeness in modern interface work.

What has no motion

  • The withheld surface and everything in it. The signature. Specified in full below.
  • Every number. No count-up, ever. These counts are findings withheld and items waiting on a person; a number that animates from zero displays a false value for 800ms, and in a compliance tool that is not a flourish, it is a wrong reading on screen.
  • Anything triggered by scroll. No reveal-on-scroll, no parallax, no fade-in-on-enter. The record is not a slideshow, and a reader scrolling back up a diff must find it exactly as they left it.
  • The diff. Before and after are paper: no blur, no shadow past a hairline, no transition, no hover.
  • The source extract and its marked span.
  • The type scale. Nothing resizes at any time.

Reduced motion removes motion. It does not shorten it.

Done. The block at the foot of strata.css used to set animation-duration: 0.01ms and transition-duration: 0.01ms, which shortens motion to the point of invisibility but leaves every animation and transition running — the events still fire, the compositor still works, and an element mid-animation at a repaint can still flash. Why this encodes the product rather than decorating it

The usual hierarchy gives the most important thing the most treatment. This inverts it, and the inversion is the argument. Everything else on a Strata screen responds to a person: a card lifts, a chip fills, a panel slides, a pill springs, a masthead lets the page show through it. One surface does not. It does not respond to the cursor, it does not join the page-load sequence, it does not float, and it does not cast a shadow. It is the only place the interface has nothing to offer, which is precisely what the system is telling the reader: we could not verify this, so we will not say it, and there is nothing here to make that easier to accept.

The test that keeps it the signature. The withheld surface must be the stillest thing on any screen it appears on. If a second element ever competes — equally still and equally prominent — the second element gets motion, or it is cut. Nothing is added to the withheld surface to win the comparison.

The focus ring is an outline, in every scheme, on every surface, glass included. The halo is an addition and may be lost without harm.

Markdown becomes DOM nodes. It never touches innerHTML.

This is a security decision before it is a design one, and clerk.js states it at the head of the file, lines 21–23: every string from the server goes in as text. textContent, never innerHTML. Grep the file — there is no innerHTML in it, and even the thumb glyphs are built with createElementNS.

The reason is specific to this product. A reply is prose that passed through a model, and a model that has read a filing has read whatever that filing contained. The corpus is 102 real public documents retrieved from eight commissions; nobody on this side wrote them. Rendering model output as markup would make the contents of a stranger's PDF into executable page structure.

So the renderer parses a deliberately short subset and appends real elements — inline() at clerk.js lines 221–242 and addTurn() at 244–282:

Bold (**…**), inline code (backticks), unordered lists (- or *), paragraphs. Links. A link whose href came from a model is a place to send somebody, and this product does not let a model choose that. Also no headings, no tables, no images, no ordered lists.

The sideways scroll, and the guard that had a hole

Two pages were scrolling sideways at 390px and had been all day, with the suite green: security.html at 414px against 390, and subprocessors.html at 477.

The cause was one rule written for a short status label: .stage b { white-space: nowrap }. It is a descendant selector, so it also caught the <b> that opens each row's sentence and held a whole paragraph on one line. A paragraph that cannot wrap sets the page's minimum width to the length of its longest sentence, and the whole document then scrolls.

The guard had a hole and that is the real lesson. tests/test_responsive.py only ever read app/web/. The marketing site was never guarded at all, which is precisely why it could scroll sideways for hours with everything green. A guard that covers the half of the product you were thinking about is how the other half goes wrong quietly.

The file now reads deploy/site/ too — SITE at line 174, then five tests. The one that matters carries the specific rule that caused this:

test_nowrap_never_reaches_prose_through_a_descendant_selector   line 223

It walks every rule in every site page and stylesheet, and fails when a block containing nowrap has a selector whose last part is a descendant and is one of b strong em i span p li td. A short label may be nowrap; a paragraph may not.

Two false positives in the test's own first drafts, kept in its docstring because they are the interesting part. A comment explaining the past bug quotes the rule that caused it, and @media (max-width: 640px) is a breakpoint — the opposite of a fixed element width. The first version flagged all seven pages for their own media query. So the helper strips comments and at-rule preludes before it reads anything (_without_comments_and_at_rules, line 192). A test that fails on the documentation of the bug it guards is worse than no test, because it gets deleted rather than fixed.

The fix itself is scoped rather than global: .stage p b { white-space: normal } gives the sentence its wrapping back while the label keeps its nowrap. Two more rules were needed and both are narrow on purpose — min-width: 0 on the stage rows, because a 1fr grid track takes its automatic minimum from the item's min-content; and overflow-wrap: anywhere on .stage code and deliberately not on code everywhere, because applied globally it also breaks the demo email address in the credentials table across two lines at full width, and that is an address a reader is meant to copy.
