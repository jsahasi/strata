Remaining gaps, prioritised

Compiled 2026-08-04 from a full audit of every document in docs/ and deploy/site/, each claim checked against the code rather than against the previous version of the document.

How to read the ordering. Priority here is not size of effort. It is what a reviewer hits first. A submission is read in a fixed order — the repository link, then the run command, then the screens, then the documents — and a defect early in that order hides everything good behind it. P0 items stop a reviewer at the front door. P1 items are false statements a reader could act on. P2 items are real code gaps that a panel question would expose. P3 items are things only we would notice.
One decision is yours. Making the repository public is an outward-facing, hard-to-reverse act, and the history contains 40-odd commit messages plus every document in this list. It is item P0-1 and it needs your word, not mine.
