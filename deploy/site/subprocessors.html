Whose machines this runs on, and what reaches them.

Sub-processors · 2026-08-04

A sub-processor is a company Strata hands your data to so that Strata can run. There are none, because there is no customer data to hand anyone. This page names the companies whose machines the site sits on anyway, says what each one gets, and says which of them becomes a sub-processor on the day a customer loads a document.

Strata is a pre-production build by one person. It has no customers, and the data in the demonstration is invented.

Nothing here is a contract. No data processing agreement is signed with any company named below, because there is no legal entity to sign one.

The short answer

No company processes customer data for Strata today. Two facts hold that up, and both are checkable in about a minute.

First, the application is not deployed. What answers at strata.sudama.ai is a handful of static pages served by nginx — the landing page, the policy pages including this one, and a sign-in page that says access is by invitation. Ask that host for /health, /projects or /chat and it returns a 404, because there is no application behind it to answer. The privacy page describes tables that exist in the code and run on a developer's own machine.

Second, nobody has an account with real documents in it. Every document in the demonstration is invented.

Why write the page at all, then. Because a buyer's procurement team asks for this list, and "we have not written one" is a worse answer than a short one. And because the list is about to change: the section below says what each company gets today and what it would get the day the application ships.

The companies that run the site

Three. None of them receives customer data today, because there is none. Each would be a sub-processor the moment the application is deployed, and each is listed now so that day does not need a new page.

DigitalOcean

What they hold. The whole machine. The static pages, the video on the landing page, the certificate's private key, and the request log nginx writes. Why. The site runs on a virtual machine rented from them. Where. DigitalOcean, LLC is a United States company; the address is 143.198.140.28, which their own registration record shows as theirs. Which region the machine sits in is not stated here, because it was not checked.

shared host

Two things a buyer should know about that machine. It is shared. The original plan gave Strata its own disposable box; no credential existed to create one, so it went onto a droplet that already serves another of the author's projects, alongside that project's commercial data. That is a smaller boundary than the plan asked for, and ADR-10 in the decision record sets out what was traded and what would move it back. And nginx logs every request by default — the address it came from, the page asked for, the time and the browser's user-agent line. How long the host keeps that log is not claimed here, because the host's log settings were not read.

GoDaddy

What they hold. The domain sudama.ai and the name servers that answer for it, ns29 and ns30.domaincontrol.com. What reaches them. The lookups that turn strata.sudama.ai into an address: the name asked for and the resolver that asked. Not the page you then read, and nothing you type into it. Why. The domain was registered there. Where. GoDaddy.com, LLC is a United States company.

Let's Encrypt

What they hold. The certificate that makes this page arrive over HTTPS, issued to the name strata.sudama.ai and to nothing else. What reaches them. The host name, and a proof that this server controls it. No person's data goes into a certificate request. Worth saying out loud. Every certificate is published to public transparency logs, so the host name is public whether or not anything on it is. Where. Issued by the Internet Security Research Group, a United States non-profit.

Anthropic, and why it is not on that list

Strata is built to call a model, and the code for it exists. A buyer should expect to see the model vendor named here. It is not named as a sub-processor because nothing is sent to it — and the reason is worth reading, because "we plan to" and "it is off" are different claims and only one of them is true.

Two modules can make the call. app/interpretation/propose.py asks a model what changed between two versions of a filing. app/chat/agent.py runs one turn of the assistant. Both were written against Anthropic's API.

Neither of them runs. Not on the deployed site, which has no application at all. Not on a local run either: nothing in the application calls the proposer, the assistant's agent is imported only by its own test, and the chat screen looks for app/chat/engine.py, which has not been written. The screen answers that the part of it which reads the record is not wired in.

And there is no key. Both modules need ANTHROPIC_API_KEY in the running process, and nothing in the repository loads the environment file into it. Without the key, both refuse and say so on the page — they do not fall back to canned text dressed up as an answer. That refusal is tested.

What would be sent, when it is wired. Passage text from regulatory filings, which carries no new exposure where it bears no confidentiality marking, because the docket has already published it. At the one step that matches a change to an internally worded obligation, only the specific obligation lines being compared — never the whole obligation register as background, never a raw uploaded file with its author and revision history inside it, and never text carrying a confidentiality marking until a person clears it. docs/security.html in the repository sets that scope out line by line, and this page does not widen it.

What is missing before Anthropic can be listed for real. Commercial terms, a data processing agreement, and an answer on retention — whether the calls run with no training on inputs and a stated retention window. None of that is agreed with anyone. Until it is, the minimisation described above is a design and not a running system.

What is not a sub-processor, and where the line is

The line is this: a sub-processor handles your data so that Strata can run for you. A tool the operator uses for his own work is not one, however much it holds about him. Padding this page with the second kind would make it longer and less useful, and it would blur the question a procurement team is actually asking.

not one

Gmail. Mail sent to the address at the foot of these pages lands in an ordinary personal Gmail mailbox, and Google's terms govern it — the privacy page says the same. That is the operator's mailbox for correspondence, not somewhere Strata puts your documents. The environment file also names Gmail credentials for a user-research outreach script; no such script exists in the repository, and no code in it sends mail.

not one

GitHub. The source lives in a private repository at github.com/jsahasi/strata. It holds the code, the invented corpus and a set of public filings downloaded from state commissions' own document systems. It holds nobody's documents.

not one

Traefik and Coolify. These appear in the decision record and they are programs on the same rented machine, not companies that receive anything. The repository's nginx configuration listens on plain HTTP only, and the public address answers over HTTPS, so a proxy in front of nginx holds the certificate; ADR-11 records which one and why it is not the one originally chosen. Nothing leaves the machine through them except the certificate request already listed above.

not one

The software libraries. FastAPI, uvicorn, SQLAlchemy, Pydantic, Jinja, httpx and the Anthropic SDK run inside the process on the same machine. A library is not a company receiving data. The only one of them that can send anything anywhere is the Anthropic SDK, and the section above says what that would be.

none

Things that are simply absent. No analytics, no error tracking, no content delivery network, no external fonts or scripts, no customer support tool, no marketing platform, no payment processor — nothing is for sale — and no off-host backup: the repository's backup script writes a verified snapshot to a directory on the same disk and has no remote destination anywhere in it. No page here fetches anything from another host, which is checkable by reading the source.

What changes on the day the application ships

This page is short because the product is not running. The honest version of it after launch is longer, and the changes are predictable enough to write down now.

  • DigitalOcean stops holding static pages and starts holding everything. The SQLite file with every uploaded document, every claim, every audit row. One company, one disk, no encryption at rest beyond what the disk gives — the security page says so and does not soften it.
  • Anthropic becomes a real sub-processor the first time a key is set and a call is wired, and gets filing text under the scope above.
  • Anything else appears here before it runs, not after. Mail sending, error tracking, a backup target, a payment processor: added to this page first.
Placeholder — required before production use A signed data processing agreement with each company named above, a way to tell customers before this list changes rather than after, and a legal entity to hold the contracts. None of those exist.

How this list was checked

Every row above came from a command or a file, not from memory. Run them yourself; they are all read-only.

  • dig +short strata.sudama.ai A returns 143.198.140.28, and whois 143.198.140.28 names DigitalOcean.
  • dig +short sudama.ai NS returns the domaincontrol.com name servers, and whois sudama.ai names GoDaddy as registrar.
  • openssl s_client -connect strata.sudama.ai:443 shows the issuer as Let's Encrypt and the subject as this host name.
  • curl -I https://strata.sudama.ai/health returns 404, which is what a host with no application behind it returns.
  • The claim that no model call runs was checked by searching the code for callers of the two modules that can make one, and by reading the chat screen's own note that its engine does not exist yet.

Where a check was not run, this page says so instead of rounding up — the machine's region and the request log's retention are both marked that way above.
